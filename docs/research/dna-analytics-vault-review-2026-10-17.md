## Implementation traceability

- Source → existing accepted normalized observations → `domain/core-performance.ts` / `domain/star-signals.ts` → existing owner-scoped profile repositories/services → new minimal presentation projection in `lib/core-performance-comparison.ts` → shared comparison component. No raw archive scan or new provider call.
- Time: best/median/population σ and median m/s are copied from the approved aggregate; milliseconds are formatted as seconds only. No new rating, confidence, smoothing or distribution is calculated.
- Scope: fixed Bike/Car/Horse and exact-distance groups; median/sample sorting is only within each group. Normal format/gates are explicitly unpartitioned; this table must not be used as exact-format Pro League evidence.
- Samples: reuse `hypothesis_only` / `minimally_analytical` from the domain; 9/10 boundary and experimental status tested. No new threshold.
- Stars: copy separate received/opportunity/eligible counts and star cutoff; gates <=3 never become negative Yellow evidence. Missing remains unknown; zero denominator does not produce 0% or infinite rate. No field-quality inference or ranking weight.
- Vault: reuse already-returned catalogue records only, with existing result-cap warning and mutation cards. Compact rows link to those cards; no mutation is added.
- Privacy: private routes/auth/forced RLS/read models unchanged; client table receives displayed profile fields only, not raw star/opponent objects. No migrations, provider connection, game action or deployment.
